# Translating Ayuless

Ayuless strings live in `TMessagesProj/src/main/res/values/ayuless.xml`
(English). Translations use `values-<Android locale>/ayuless.xml`.
Only Ayuless strings are synchronized with Crowdin; Telegram's existing
translations remain managed upstream. No Crowdin SDK or network service is
added to the app. Translations ship inside the APK.

## Contributing

Translate on [Ayuless on Crowdin](https://crowdin.com/project/ayuless),
or submit an XML translation directly in a pull request. Preserve resource
names, Android escaping and format arguments such as `%1$s` and `%2$d`.
Do not translate entries marked `translatable="false"`.
Partial translations are welcome: missing strings use the English fallback.

Run these checks from the repository root:

```sh
python3 Tools/localization/sync_translations.py
python3 -m unittest discover -s Tools/localization -p 'test_*.py'
```

## Connecting Crowdin (maintainer)

1. Create a file-based project on Crowdin, set English as its source language,
   and select the target languages. Grant the integration account access to
   this project.
2. In GitHub repository **Settings → Secrets and variables → Actions**, add
   these repository secrets:
   - `CROWDIN_PROJECT_ID`: the numeric Crowdin project ID.
   - `CROWDIN_PERSONAL_TOKEN`: a Crowdin personal access token restricted to
     this project, with permissions to manage source files and import/export
     translations. The initial seed also needs translation import access.
   Do not put tokens in issues, commits, workflow inputs or `crowdin.yml`.
3. Under **Settings → Actions → General → Workflow permissions**, enable
   **Allow GitHub Actions to create and approve pull requests**. The workflow
   opens PRs; it does not approve or merge them.
4. Add the Actions repository variable `CROWDIN_ENABLED` with value `true`.
   Before this variable is enabled, the synchronization job is skipped.
5. Run **Actions → Crowdin translations → Run workflow**, enabling
   `seed_existing_translations` for the first run. This uploads the English
   source and existing repository translations. Imported translations are
   not automatically approved: review and approve them in Crowdin.
6. Share the project's public translation URL with contributors. Subsequent
   runs do not need the seed option. Sync runs daily, on English source
   changes, and manually.

The integration exports approved translated strings into ignored `.crowdin/`
staging files. It checks XML, resource names, empty strings and format argument
compatibility before merging the complete batch. Partial downloads preserve
existing repository entries, including translations not yet approved on
Crowdin. To intentionally remove an old translation, remove it in the repository
as well. Review the resulting `l10n/crowdin` PR before merging.

The integration uses the repository's `GITHUB_TOKEN` to open its PR. GitHub
normally does not trigger further PR workflows for events generated by that
token. Local validation runs inside the sync job; dispatch the Build workflow
manually for the translation branch when a build is needed before merging.

New Ayuless-only languages are included in both the binary translation assets
and the generated runtime locale lookup. Existing Telegram strings continue
to use their normal fallback if that language is not bundled upstream.
`languages_mapping` in `crowdin.yml` keeps existing language-wide resource
directories such as `values-ru` and `values-es`; Crowdin's default Android
codes may include a region. Keep this mapping when importing existing files.

Configuration references: [Crowdin GitHub Action](https://github.com/crowdin/github-action),
[Crowdin configuration](https://support.crowdin.com/developer/configuration-file/),
[Android XML format](https://store.crowdin.com/android-xml).
