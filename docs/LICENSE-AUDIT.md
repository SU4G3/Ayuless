## Can the combined work be GPL-3.0-or-later?

Yes, with the caveats below.

| Check | Result |
|---|---|
| Java/Kotlin files in `TMessagesProj*/src` | 3000 |
| Files with header "GNU GPL v. 2 or later" | 437 |
| Files mentioning GPL but **without** "or later" | 0 |
| Files with no license header at all | 1851 (covered by repo-level license) |
| Apache-2.0 headers (androidx copies, audioinfo, customtabs, `me.vkryl`, ...) | 114 |
| BSD headers (`org.telegram.PhoneFormat`) | 4 |
| LGPL / MPL headers | 0 |

Commands used (bash):

```bash
I="--include=*.java --include=*.kt"
grep -rlE "GPL v\. ?2 or later" $I . | wc -l
grep -rlE "GNU GPL|GPL v" $I . | xargs grep -L "or later"
grep -rL "GPL" $I TMessagesProj/src | wc -l
grep -rl "Apache License" $I . | wc -l
```

## Notes

- **Header-less files.** The upstream repo ships the plain GPLv2 text as `LICENSE`, while every file that has a header says "v2 or later". We treat header-less upstream files the same way (this is also how Telegram-FOSS and other forks have treated them). Kept upstream license text as `LICENSE.GPL-2.0`.
- **Apache-2.0** code is compatible with GPLv3 (but not GPLv2-only), so moving to v3 is fine.
- **BSD** code is compatible with both.
- **Apache-2.0** libraries from Maven: the UnifiedPush connector (`org.unifiedpush.android:connector`) and its Tink dependency (`com.google.crypto.tink:tink`, pure Java, not Google Play services).
- **CC BY 4.0** artwork: the Solar icons (`TMessagesProj/src/main/res/drawable/ayuless_solar_*.xml`) are licensed under CC BY 4.0, which is one-way compatible with GPLv3 (CC BY 4.0 material may be included in a GPLv3 work). Attribution is kept in [CREDITS.md](CREDITS.md) and in each file's header comment.
- **Native submodules** need their licences checked at the pinned revisions, including optional components and transitive Rust dependencies. The expected upstream permissive/LGPL licences do not establish the contents of missing submodules. FFmpeg must be built without `--enable-nonfree`.

## Dependency and binary audit status

The Java header snapshot above is not a complete audit of assets or recursive
dependencies. Current F-Droid blockers and verification status are tracked in
[fdroid/CHECKLIST.md](fdroid/CHECKLIST.md).

- `TMessagesProj/jni/prebuild/lib/**/*.a`: the committed copies have been removed. CI builds all 64 static archives from pinned source submodules ([NATIVE.md](NATIVE.md)). A prebuilt archive is not inherently proprietary; F-Droid needs a source build and compatible licensing of its inputs.
- ~~`TMessagesProj/libs/libgsaverification-client.aar`~~: closed Google binary, removed in #14 (`Tools/check_degoogle.py` fails the build if it comes back).
- Proprietary Gradle SDKs (GMS, Firebase, ML Kit, Play Integrity, billing and Play credentials provider) have been removed from the active build; see [DEGOOGLE.md](DEGOOGLE.md). The excluded Huawei distribution and SDK keep rules have now also been removed. Full transitive resolution still needs review; cached POM evidence is in [fdroid/DEPENDENCIES.md](fdroid/DEPENDENCIES.md).
- WidgetJS `.qbc` is generated by Gradle with the repo's QuickJS/shim/compiler sources; all eight committed copies and unused web WASM are removed. The three builtin JS sources are now restored from TelegramMessenger/quickjs commit `b526a817f188ef861eea7666d68361c7851673a0` (MIT). The host bootstrap, Android engine and WidgetJS compiler regenerate builtin bytecode from them rather than trusting the old vendored headers. See [fdroid/VALIDATION-2026-11-13.md](fdroid/VALIDATION-2026-11-13.md).
- Solar artwork attribution is also packaged in `assets/ayuless-notices.txt`. Dependency `licences/` directories are no longer excluded by the root packaging configuration. Verify notices in the built APK.

## Bundled resource inventory (offline, 2026-11-12)

[ASSET-INVENTORY.tsv](fdroid/ASSET-INVENTORY.tsv) enumerates local Android
assets and resources in the five configured modules, with SHA-256, component,
licence status and source. Regenerate with `python3 Tools/fdroid/asset_inventory.py`.
It includes all resource qualifiers and source-set overlays, not only `raw/`.
The source URL for an inherited resource identifies its upstream distribution;
it is **not** proof of the original author's grant or preferred editable source.
`UNKNOWN` and `pending` entries mean that the offline inventory did not establish
a file's grant. They are not proof of a non-free licence or an automatic ban on
distribution. The confirmed Apple emoji provenance concern is distinct from
unconfirmed upstream asset ownership. The inventory excludes notices themselves
and generated WidgetJS; initialized submodules are now covered by source scanning,
but their licences and the final merged APK still need individual review.

Replacing unknown OCR weights, icon-font glyphs or emoji with arbitrary files
would break features and would not establish provenance. Review grants per
component rather than labeling all unknown files proprietary. F-Droid permits
redistributable non-free decorative assets with `NonFreeAssets`; the label does
not create redistribution permission. No such label is added without identifying
the relevant assets and their actual terms.

## Follow-up evidence (2026-11-17)

[FONT-LICENSE-SOURCES.json](fdroid/FONT-LICENSE-SOURCES.json) pins the original
font licence files and hashes. The text fonts are retained without modification;
missing byte-identical source-build provenance is not by itself a reason to
replace an otherwise licensed font. See
[ASSET-REVIEW-2026-11-17.md](fdroid/ASSET-REVIEW-2026-11-17.md).

[UPSTREAM-ASSET-PROVENANCE.tsv](fdroid/UPSTREAM-ASSET-PROVENANCE.tsv) independently
compares Git blob hashes against Telegram `7be672ea`: 5,345 resources match
byte-for-byte. This establishes distribution provenance, not ownership or a new
licence grant. Unknown individual grants remain review questions rather than
proof of non-free content or a requirement to replace all Telegram resources.
