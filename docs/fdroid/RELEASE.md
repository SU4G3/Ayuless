## Что нужно от владельца проекта

1. Зафиксировать результат теста UnifiedPush: название дистрибьютора, какой APK
   установлен, доставка при свёрнутом приложении и выключенном экране. Проверить
   второй аккаунт, переключение на «Нет», удаление/повторную регистрацию
   дистрибьютора. Android force-stop через системные настройки — отдельный
   сценарий; он не равен обычному закрытию приложения.
2. На **итоговом** APK проверить новый вход, мини-приложения, Noto-эмодзи и
   смешанные тона рук, уведомления и карту/спутник/гибрид с видимой атрибуцией.
   Старый рабочий APK не подтверждает изменения, которых в нём ещё нет.
3. Сделать 3–5 настоящих скриншотов на тестовом аккаунте без личных данных:
   список чатов, настройки Ayuless, Ghost, Spy/история правок и уведомления.
   Поместить PNG/JPEG в
   `fastlane/metadata/android/{ru-RU,en-US}/images/phoneScreenshots/`.
   Скриншоты полезны для магазина; их отсутствие само по себе не доказывает
   нарушение inclusion policy.
4. Если уже есть ответы авторов или ссылки на лицензии спорных ресурсов —
   сохранить их в репозитории. Простого утверждения владельца форка о правах
   на чужой ресурс недостаточно. При отсутствии подтверждений нужно получить
   разрешение у правообладателя либо заменить конкретный ресурс.

## Что ещё требуется завершить в исходниках и среде сборки

| Работа | Что считается результатом |
| --- | --- |
| Унаследованные ресурсы | Уточнены гранты для `fonts/gram.ttf`, `fonts/num.otf`, `secureid_ocr_nn.dat`, `PhoneFormats.dat`, `shapes.dat`, моделей; установлены версии/лицензии остальных шрифтов и происхождение анимаций/звуков/изображений. Список файлов и хешей — `ASSET-INVENTORY.tsv`; известные исключения — `../LICENSE-AUDIT.md`. `UNKNOWN` означает нехватку доказательств, а не установленную несвободную лицензию |
| Лицензионные уведомления | Нужные copyright/licence/NOTICE действительно присутствуют в исходниках и итоговом APK, включая зависимости UnifiedPush |
| Карты | Проверены именно используемые endpoint/слои и их условия, ссылки атрибуции работают. EOX разрешает использовать свой онлайн-сервис с атрибуцией, но это не универсальный грант на распространение всех его изображений |
| Идентификация входа | Ревью явно учитывает API ID 4, официальный fingerprint и LoginSpoof. Выбранный пользователем профиль сохранён; новая регистрация API ID не объявляется обязательной без конкретного требования |
| Сборка по рецепту | Полностью проходят подготовка, сканирование, offline native/WidgetJS build и unsigned APK без `release.keystore` в актуальной среде F-Droid |
| Проверка APK | Версия/код/ID, подпись, packaged notices, `Tools/test_noto_emoji.py` и бинарный сканер проверены на **этом** APK |

Не нужно получать отдельное письмо для каждого GPL-файла, если применимый грант
уже установлен. Не нужно отмечать все непроверенные файлы как `NonFreeAssets`:
Anti-Feature не выдаёт разрешение на распространение. Полное совпадение двух APK
желательно, но upstream reproducible signing не включено в этот рецепт; это не
самостоятельное обязательное условие включения.

На проверенной локальной машине есть KVM/libvirt, но нет исполняемого Vagrant и
готовой F-Droid buildserver VM. Поэтому успешная Java-компиляция не закрывает
серверную сборку. Настройка builder и исправление выявленных ошибок — работа по
подготовке сборки; владельцу не нужно вручную переписывать native-рецепт.

## Проверка рецепта на подготовленном builder

Использовать официальную среду, описанную в
[F-Droid buildserver](https://f-droid.org/en/docs/Build_Server_Setup/).
Не запускать scanner на рабочем checkout: он может удалять файлы.

Из отдельного checkout `fdroiddata`:

```sh
# AYULESS_SOURCE — абсолютный путь к проверяемому checkout Ayuless.
cp "$AYULESS_SOURCE/docs/fdroid/org.ayuless.messenger.yml" metadata/
fdroid readmeta
fdroid lint org.ayuless.messenger
```

Рецепт должен ссылаться на точный публичный коммит с UnifiedPush, Noto и
последними build-исправлениями. Для проверки в **локальной копии метаданных**
убрать `disable` у этой сборки, сохранив блокеры в документации. Не применять
`--force` или `--skip-scan`: они могут скрыть реальные ошибки.

```sh
fdroid build --server --test --scan-binary org.ayuless.messenger:72919
```

Нужны лог подготовки и сборки, полученный unsigned APK и source tarball.
Проверить APK скриптом из того же коммита:

```sh
python3 Tools/test_noto_emoji.py /absolute/path/to/built.apk
```

Pillow с поддержкой WebP нужен для этой проверки, CairoSVG — только для
регенерации уже сохранённых Noto-ресурсов. Полный native build включает четыре
ABI; готовый GitHub binary cache не заменяет сборку F-Droid.

## Тег и подача после устранения блокеров

Android сейчас сообщает `versionName=13.2.1`, afat `versionCode=72919`.
Маркетинговые GitHub-теги `v0.1.0-alpha.*` этому не соответствуют. Принята схема
`fdroid-<versionName>-<afatCode>`: первый кандидат — `fdroid-13.2.1-72919`.
Рецепт проверяет только эту группу тегов. `AutoUpdateMode: None` сохраняется до
первой успешно проверенной сборки.

После проверки и объединения нужных PR создать **новый** тег на точном
проверенном релизном коммите. Не передвигать старые теги. При следующих релизах
увеличивать Android versionCode, даже если версия Telegram не изменилась.

Далее:

1. Включить проверенный build block, указать финальный тег/коммит, обновить
   `CurrentVersion` и `CurrentVersionCode`, приложить реальные changelog/screenshots.
2. Повторить `fdroid readmeta`, `fdroid lint` и сборку на финальной версии.
3. Открыть MR из своего форка `fdroid/fdroiddata` с файлом
   `metadata/org.ayuless.messenger.yml`, ссылками на исходники/тег и лог сборки.
   Для подачи от имени владельца нужен его GitLab-аккаунт или явно назначенный
   сопровождающий. Секретный signing key и доступ к GitHub Secrets не нужны.
4. Указать `NonFreeNet` (Telegram) и `Ads` (возможность спонсорских сообщений).
   Остальные Anti-Features добавлять по фактам, а не для обхода лицензирования.
5. Дождаться review и публикации F-Droid. Наличие MR не означает, что приложение
   принято. F-Droid подпишет APK своим ключом; установка поверх APK с другим
   ключом подписи не обновится обычным способом. Перед сменой установки
   сохранить нужные локальные данные и вложения отдельно.

Приготовленный текст для MR (после устранения блокеров):

> Add Ayuless (`org.ayuless.messenger`), a GPL-3.0-or-later Telegram Android fork
> with ghost controls, local message retention, edit history and UnifiedPush.
> Native libraries and WidgetJS/QuickJS bytecode are built from pinned source.
> Emoji use Noto artwork with retained SVG sources and packaged notices.
> Required Telegram service and optional sponsored messages are disclosed as
> NonFreeNet and Ads. See the linked release tag, build log and licence audit.

Перед отправкой добавить реальные ссылки на тег/успешный лог. Этот текст не
утверждает, что нерешённые проверки уже выполнены.
