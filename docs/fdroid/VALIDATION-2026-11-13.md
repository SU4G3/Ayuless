## Scanner cleanup rationale

The unprepared source scan found 4,656 fatal findings, mostly upstream test
corpora: BoringSSL fuzz inputs, WAMR test executables and cctz timezone fixtures.
The recipe removes these unused files, sample static archives, mobile demos and
unused Media3 Cast/Cronet/IMA distributions. Their declarations are removed from
the Media3 settings, and the application-unused publishing script is emptied.
Runtime modules in the resolved dependency graph are preserved.

The only `scanignore` covers nine `.bin` files in `models/diamond_ios`.
`DiamondRenderer.readFloats` reads these as little-endian floating-point geometry
and animation arrays; they are not executable code. This does **not** assert a
licence for the artwork. An unused Playwright WebP decoder WASM is deleted after
npm preparation. esbuild's executable is rebuilt from source after scanning;
it is not hidden with `scanignore`.

  Merriweather 2.002/2.101; family licences are available, but exact-file

  The Apple-derived emoji were subsequently removed: the built-in pack and all
  handshake layers now build offline from pinned Noto SVGs. Their licences,
  copyright notices and source hashes are retained in `branding/noto-emoji`.
  The remaining review concerns upstream fonts, models, sounds and animations.
  Do not automatically label every unknown entry
  proprietary or claim every licence has been established.
- **Server/native build:** execute the whole enabled recipe in an F-Droid VM,
  including Rust source vendoring, offline native compilation and unsigned APK
  production without a release keystore. Local Java/source checks do not replace
  that build. The editing host has no configured F-Droid/Vagrant builder; the
  Python Vagrant wrapper's box-list probe fails because the Vagrant executable
  is not installed.
- **Reproducibility:** compare two clean full APK/native builds; only WidgetJS
  and builtin-header comparisons have been completed here. This is a quality
  goal, not an unconditional inclusion blocker: the recipe does not request
  upstream-signature copying through `Binaries`.
- **Release identity:** the draft pins candidate `e2a9d4877b0da7c097c94d132195910da824dd11`;
  select the reviewed release and a tag scheme matching the app's versions. Keep automatic build creation off until
  that scheme and an enabled recipe have passed review.
- **Device validation:** the user confirmed the previous PR #62 APK and mini-apps
  worked. A new APK containing these native changes still requires validation.

The current F-Droid inclusion policy allows non-free decorative assets with
redistribution permission and the appropriate `NonFreeAssets` label. It does
not require a free licence or editable source for every image/model/font.
An unidentified grant still needs investigation; adding a label cannot grant
rights that a distributor does not have. Screenshots are presentation work,
not a substitute for a build or licence review.
